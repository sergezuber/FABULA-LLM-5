# Как участвовать в FABULA-LLM-5

[English](CONTRIBUTING.md) · [中文](CONTRIBUTING.zh-CN.md) · [Русский](CONTRIBUTING.ru.md)

Спасибо за интерес к проекту! Это автономная агентная оболочка, рассчитанная в первую очередь на локальные модели. Слой надзора — проверочные барьеры, чекпоинты, защита от зацикливания, чеки о выполнении — заставляет любую модель (она подключается как сменный модуль) сдавать проверенную работу. Особенно ценен вклад, после которого всё по-прежнему работает **полностью офлайн, на обычном железе**.

## Базовые правила

- **Один плагин = один файл = один экспорт.** Каждый `plugin/fabula-*.ts` экспортирует ровно одну фабрику `Fabula*` и больше ничего. Движок вызывает *каждый* экспорт файла плагина как плагин, так что случайно экспортированный хелпер ломает загрузку. Общие хелперы живут в `plugin/lib/`.
- **Манифест — закон.** Каждый новый инструмент, плагин или внешняя зависимость объявляется в `plugin/lib/manifest.ts` (с командами `check` и `install`), после чего пересобирается сводка: `bun scripts/install-deps.ts --md > DEPENDENCIES.md`. Локализованные имя и описание плагина плюс теги возможностей добавьте в `plugin/lib/i18n.ts` (словарь тегов тот же, что в таблице плагинов README).
- **Документация движется вместе с кодом.** Возможность, не отражённая в `README.md` / `docs/` в том же PR, считается недоделанной.
- **Секреты в репозиторий не попадают.** Ключи живут только в `.env` / `*.key` (в gitignore). Шаблоны (`.env.example`, `fabula.config.example.json`) содержат только заглушки.

## Тестирование

Зелёный `bun test` может скрыть плагин, который не загружается в живой оболочке, — юнит-тесты необходимы, но их недостаточно.

Наборов тестов **три**, и каждый покрывает слой, до которого остальным не дотянуться. Правку адаптера или
движка плагинный набор не проверяет, каким бы зелёным он ни был. Ровно через эту щель пять тестовых
файлов адаптера докатились до нуля тестов — а `pytest -q` рапортовал об успехе.

```bash
cd plugin  && bun install && bun test                       # plugins: unit + corner + wiring
cd proxy   && python3 -m pytest -q                          # the :1235 adapter (watchdogs, admission, framing)
cd engine/packages/opencode && bun typecheck && bun test test/session test/task test/tool
```

Затем проверьте на **настоящем изолированном движке**:

```bash
ISO=$(mktemp -d)
XDG_DATA_HOME="$ISO" fabula serve --port 5099 --hostname 127.0.0.1 &
# check the log for 0 ERROR / failed-to-load lines, and that models/providers appear
```

Новые инструменты гоняйте через их настоящий `execute()` на живых бэкендах. «Выглядит правильно» — это не проверка.

## Пул-реквесты

- PR должен быть сфокусированным; объясняйте *зачем*, а не только *что*.
- Следуйте стилю окружающего кода — включая плотность комментариев.
- Если правка затрагивает macOS-приложение, пересоберите его командой `./build.sh` из корня репозитория (фронтенд, бинарь движка и бандл приложения — один только `app/build.sh` оставит приложение с устаревшим движком). Затем запустите `bash scripts/verify-deploy.sh` и напишите, что именно вы прокликали при проверке.

## Как сообщить об ошибке

Откройте issue и укажите: что запускали, чего ждали, что произошло, хвост лога движка и вашу конфигурацию (версия macOS, модель, локально или облако). Обо всём, что касается безопасности, — см. [SECURITY.ru.md](SECURITY.ru.md).
