# Как участвовать в FABULA-LLM-5

[English](CONTRIBUTING.md) · [中文](CONTRIBUTING.zh-CN.md) · [Русский](CONTRIBUTING.ru.md)

Спасибо за интерес! FABULA — автономная агентная оболочка, рассчитанная в первую очередь на работу без сети. Проверенную работу здесь сдаёт не модель, а слой надзора вокруг неё: гейты проверки, чекпоинты, защита от зацикливания, чеки о выполнении. Модель — сменный модуль, подойдёт любая. Особенно ценны правки, после которых всё по-прежнему работает **полностью офлайн и на обычном железе**.

## Базовые правила

- **Один плагин = один файл = один экспорт.** В `plugin/fabula-*.ts` должна быть ровно одна фабрика `Fabula*` — и больше ничего. Движок принимает за плагин *любой* экспорт из такого файла, так что забытый рядом хелпер обрушит загрузку. Общим хелперам место в `plugin/lib/`.
- **Манифест — закон.** Новый инструмент, плагин, внешняя зависимость — всё объявляется в `plugin/lib/manifest.ts`, с командой `check` и командой `install`. Потом пересоберите сводку: `bun scripts/install-deps.ts --md > DEPENDENCIES.md`. А в `plugin/lib/i18n.ts` допишите локализованные имя и описание плагина, а к ним теги возможностей — словарь тегов тот же, что в таблице плагинов README.
- **Документация едет вместе с кодом.** Возможность, которую не описали в `README.md` / `docs/` тем же PR, считается недоделанной.
- **Секретам в репозитории не место.** Ключи держите только в `.env` / `*.key` — эти файлы под gitignore. В шаблонах (`.env.example`, `fabula.config.example.json`) — одни заглушки.

## Тестирование

Зелёный `bun test` ничего не говорит о плагине, который не загрузится в живой оболочке. Юнит-тесты нужны, но их мало.

Наборов тестов **три**, и каждый достаёт до слоя, куда остальным не дотянуться. Правку адаптера или
движка плагинный набор не проверяет — хоть он весь зелёный. Ровно в эту щель провалились пять тестовых
файлов адаптера: они не давали ни одного теста, а `pytest -q` при этом рапортовал об успехе.

```bash
cd plugin  && bun install && bun test                       # plugins: unit + corner + wiring
cd proxy   && python3 -m pytest -q                          # the :1235 adapter (watchdogs, admission, framing)
cd engine/packages/opencode && bun typecheck && bun test test/session test/task test/tool
```

Дальше проверьте на **настоящем изолированном движке**:

```bash
ISO=$(mktemp -d)
XDG_DATA_HOME="$ISO" fabula serve --port 5099 --hostname 127.0.0.1 &
# check the log for 0 ERROR / failed-to-load lines, and that models/providers appear
```

Новые инструменты гоняйте настоящим `execute()` по живым бэкендам. «Выглядит правильно» — не проверка.

## Пул-реквесты

- Один PR — одна тема. Пишите *зачем*, а не только *что*.
- Держитесь стиля соседнего кода — плотность комментариев тоже считается.
- Задели macOS-приложение — пересоберите его из корня репозитория командой `./build.sh`: она соберёт фронтенд, бинарь движка и бандл приложения. Одного `app/build.sh` мало, приложение останется на старом движке. Затем запустите `bash scripts/verify-deploy.sh` и напишите, что именно прокликали при проверке.

## Как сообщить об ошибке

Откройте issue и укажите: что запускали, чего ждали, что вышло на самом деле, хвост лога движка и свою конфигурацию — версия macOS, модель, локально или облако. Всё, что касается безопасности, — по правилам [SECURITY.ru.md](SECURITY.ru.md).
