## Что такое FABULA?

FABULA — агентная оболочка, построенная на одном принципе: **надёжность живёт в системе вокруг модели, а не в самой модели.** Любая LLM — локальная на вашей машине или топовая облачная — подключается как сменный модуль. Каждый шаг работы обеспечивается движком, а не промптом, который модель вольна проигнорировать: нельзя объявить «готово», пока тесты не прошли по-настоящему; нельзя закончить раньше, чем выполнена просьба; нельзя незаметно сбиться с курса, зациклиться или бросить работу.

Запустите её полностью локально — и ничто не покинет вашу машину. Дело не в экономии: именно такой режим нужен там, где требуется аудит, — проверенный чек от модели, которой владеете вы, весит больше, чем непроверяемое заявление модели, которую вы арендуете.

![Как работает FABULA](docs/assets/how-it-works.svg)

## Почему именно «FABULA»?

*Fabula* по-латыни — «история, рассказ». Каждый агент, с которым вы работали, заканчивает сложную задачу именно им: уверенным абзацем о работе, которой, возможно, не существует. FABULA устроена так, что работа не может закончиться рассказом: сессия завершается ровно в одном из двух честных состояний — **VERIFIED** с воспроизводимым чеком или явное **NOT DONE** поверх настоящего вывода упавших тестов. Имя — это сам провал; продукт — отказ так заканчивать.

## Каждый знакомый вам провал локального агента, запрещённый движком

**«Сказал „готово“, а ничего не работает».**
Здесь «готово» — это результат тестов. После правки исходников движок сам возвращает ход в работу, пока собственные тесты проекта реально не прошли, — это часть цикла выполнения, а не строчка в промпте.

**«Написал тест, который ничего не доказывает».**
Оболочка запускает новый тест модели на коде *до патча*. Прошёл и там? Репродукция фальшивая — «готово» отклонено. Сломал соседний тест? Регрессия — «готово» отклонено.

**«Бросил на полпути».**
Закончить ход — не решение модели. Независимый судья читает реальные вызовы инструментов, а не пересказ модели, и не даёт остановиться, пока просьба не выполнена. Когда замеренная траектория — красные проверки, непроверенные правки, откаты — противоречит модельному «готово», оно отменяется без разговоров.

**«Закапывался всё глубже».**
Две проваленные проверки подряд — и оболочка откатывает все файлы к последнему зелёному снимку (в собственном теневом хранилище; ваш `.git` не тронут), после чего подсказывает другой подход, называя повторяющуюся корневую причину. Побочные эффекты, которые откатом файлов не отменить, — установка пакета, миграция, POST-запрос — помечаются, а не забываются.

**«Гонял один и тот же поиск по кругу».**
Байт-в-байт одинаковые вызовы и почти совпадающие запросы движок обрезает по замеренному бюджету. А когда поисковый ход остановлен, оболочка сама отдаёт честное «не нашёл» со списком того, что было испробовано, — вместо хода, потраченного впустую.

**«Утонул в контексте».**
Контекстное окно принадлежит одному вызову, а не разговору. Чекпоинты переносят состояние через потолок, слишком большой материал держится вне контекста и читается оттуда ограниченными порциями — сессия живёт дольше окна.

**«Агентные оболочки жгут в 4× больше токенов».**
Эта — экономит. Цена шага упала на **45%, замерено по реальному трафику**: префикс запроса сократился с 72.3k токенов до менее чем 40k и внутри задачи остаётся байт-стабильным, так что KV-cache модели переживает шаги. Поэтому маленькая локальная модель держит темп работы на ноутбуке.

## Не верьте на слово. Воспроизведите.

![Докажи](docs/assets/prove-it.jpg)

Каждая работа, прошедшая все гейты, выписывает **чек о выполнении** (Proof-of-Done receipt): diff, команда проверки, модель, которая была подключена в этот момент, и sha256-отпечаток точного контекста, из которого родилась работа, — префикс промпта, схемы инструментов, профиль роутера, текст запроса, дескриптор модели на сервере, а по желанию — настоящий дайджест файлов весов на диске. Ни один другой выпущенный агент не публикует такой артефакт в виде открытой воспроизводимой спецификации; знаете такой — откройте issue.

Запись реальной работы закоммичена дословно — воспроизведите её:

```bash
cd demo && fabula receipt verify
```

```
VERIFIED ✓ — the artifact replayed deterministically:
base c660a02ab138 + patch → `bun test` passed.
```

Есть и результат потяжелее, тоже публичный: настоящая задача [SWE-bench Pro](https://github.com/scaleapi/SWE-bench_Pro-os), решённая от начала до конца локальной моделью на одной обычной машине и оценённая *скрытым* приёмочным набором бенчмарка — **100% скрытых тестов прошли, вердикт RESOLVED**, — с воспроизведением в Docker одной командой: [`docs/receipts/`](docs/receipts/).

Модель не стала умнее. Система вокруг неё просто не позволила «готово» случиться без доказательства.

Неотредактированные артефакты этой работы:

- [`refusal.cast`](docs/assets/refusal.cast) — живая запись терминала с тем самым отказом (проигрывается asciinema)
- [`captured-run.svg`](docs/assets/captured-run.svg) — та же сессия, отрисованная шаг за шагом
- [`HARDEST-JOURNEY.ru.md`](docs/HARDEST-JOURNEY.ru.md) — самый тяжёлый день: серия красных проверок, автоматический откат, второе мнение по подсказке оболочки

Формат чека — открытая спецификация, реализовать её может любой агент: [verified-autonomy receipt v0.2](docs/spec/verified-autonomy-receipt-v0.2.md) — JSON-схема, правила честности по каждому полю и протокол воспроизведения. FABULA — её эталонная реализация: [`docs/GREENPAPER.ru.md`](docs/GREENPAPER.ru.md).

## Установка

**Понадобятся:** [LM Studio](https://lmstudio.ai) с моделью, умеющей вызывать инструменты (или любой
OpenAI-совместимый endpoint), и `git`. Всё остальное — движок, Bun, локальный адаптер, зависимости
плагинов — поставит `setup.sh`.

### macOS — настольное приложение

Apple Silicon и Xcode Command Line Tools (при сборке движка компилируется несколько нативных модулей).

```bash
xcode-select --install   # once per machine; skip if you already build C/C++
```

```bash
git clone https://github.com/sergezuber/FABULA-LLM-5 && cd FABULA-LLM-5
./setup.sh
open FABULA-LLM-5.app
```

### Linux

```bash
git clone https://github.com/sergezuber/FABULA-LLM-5 && cd FABULA-LLM-5
./setup.sh
bin/fabula serve --port 4096      # then open http://127.0.0.1:4096
```

Движок и все плагины работают здесь в полном составе. Настольное окно собирается отдельно и упаковывается в `.deb`:
`bash shell/build.sh`.

### Windows

Сначала поставьте **Git for Windows** — оболочка выполняет каждую команду через один и тот же
POSIX-шелл на всех платформах, чтобы у правил безопасности была одна грамматика для разбора.

```powershell
git clone https://github.com/sergezuber/FABULA-LLM-5; cd FABULA-LLM-5
.\setup.ps1
bin\fabula.exe serve --port 4096   # then open http://127.0.0.1:4096
```

`setup.sh` (или `setup.ps1`) можно перезапускать когда угодно — после `git pull`, после установки зависимости. Ваши `.env` и `fabula.config.json` он никогда не перезаписывает.

### Подключите модель

**Локально (по умолчанию):** откройте LM Studio, загрузите модель с поддержкой вызова инструментов, запустите её сервер. Локальный адаптер, на который смотрит конфиг, `setup.sh` уже поставил — больше ничего делать не нужно.

<details>
<summary><b>Любой OpenAI-совместимый endpoint</b> — облачный провайдер или корпоративный шлюз</summary>

Ключ положите в `.env` (файл под gitignore), провайдер опишите в `fabula.config.json`:

```jsonc
// .env
MY_API_KEY=sk-...

// fabula.config.json
{
  "model": "myapi/my-model-id",
  "provider": {
    "myapi": {
      "name": "My endpoint",
      "npm": "@ai-sdk/openai-compatible",
      "options": { "baseURL": "https://llm.example.com/v1", "apiKey": "{env:MY_API_KEY}" },
      "models": {
        "my-model-id": { "tools": true, "limit": { "context": 131072, "output": 32768 } }
      }
    }
  }
}
```

Модель обязана поддерживать **вызов инструментов**, а в `limit` нужны оба поля — `context` и `output`. Проверить endpoint и точный id модели: `curl -s https://llm.example.com/v1/models -H "Authorization: Bearer $MY_API_KEY"`.

</details>

### Первый запуск — доказательство за две минуты

В [`demo/`](demo/) заранее подложен баг — и все тесты там при этом зелёные.

1. Откройте `demo/` как проект.
2. Вставьте: *Исправь баг экспорта: ночная выгрузка молча теряет строки с датой, равной дате конца периода. Докажи.*
3. Смотрите, как система отказывается заканчивать, пока не появится доказательство.

Вы увидите, как она напишет тест, убедится, что тест падает на старом коде, и только после этого назовёт работу сделанной — на вашей машине, на вашей модели.

## Что внутри

| Гейт | Что он отклоняет |
|---|---|
| **verify** | «Готово» без прошедших собственных тестов проекта — движок сам возвращает работу в проверку. |
| **reproduce** | Правку, чей новый тест проходит и на коде до патча (фальшивая репродукция) или ломает соседний (регрессия). |
| **quiz** | Изменение, которое агент не может объяснить, — ответы оцениваются по его же diff, и только потом «готово» засчитывается. |
| **attest** | Текстовый результат, утверждающий больше, чем позволяют источники: цитаты ищутся дословно, числа перепроверяются, «прочитал все N файлов» сверяется с журналом чтений самой сессии. |
| **judge** | Ход, который заканчивается раньше, чем выполнена просьба, — с жёстким вето, когда замеренная траектория противоречит модельному «готово». |
| **rewind** | Закапывание вглубь — серия красных проверок атомарно откатывает файлы к последнему зелёному чекпоинту. |
| **go floor** | Изменение в Go, о котором не спросили его собственных анализаторов: шесть штук запускаются один раз на зелёной проверке, и *достижимая* уязвимость блокирует, а простое присутствие в зависимостях — нет. |
| **re-checking** | Чек, утверждающий больше, чем было проверено на деле: каждое заявление об идентичности попадает ровно в одно именованное состояние — перепроверено здесь, непроверяемо здесь или расхождение. |
| **provenance** | Работу неизвестного происхождения — каждый чек несёт отпечаток точного контекста, из которого она родилась. |
| **escalate** | Топтание в тупике: когда замеренные данные говорят, что ещё одна локальная попытка не стоит своей цены, оболочка сама запрашивает из облака одно второе мнение; за рулём остаётся локальная модель. |
| **memory** | Память, которой верят, вместо того чтобы проверять: запись привязана к коду, из которого она родилась, и перед выдачей перепроверяется по вашему реальному дереву. По умолчанию выключена; её решения сначала идут в теневом режиме, пока вы их не прочитали. |

Вокруг гейтов: веб-исследование, шелл, выполнение кода в песочнице, правки файлов, устойчивые к сдвигам текста, автоматизация браузера, долговечные передачи состояния, чекпоинты с откатом и защита от SSRF, утечек секретов и промпт-инъекций.

Эти защиты закрывают **три двери, а не одну**: правило, останавливающее инструмент, останавливает то же действие и через шелл, а код без контейнера выполняется под профилем ядра ОС. Агент, которого попросили поставить что-нибудь в автозапуск, попробует все три двери — не ради атаки, просто чтобы закончить задачу.

Полная карта — 40 плагинов, 90 инструментов: [`docs/PLUGINS.ru.md`](docs/PLUGINS.ru.md).

Поверх чека строится опциональная **экономика доказательств** — публикация в контентно-адресуемый реестр, независимое подтверждение сторонней моделью-свидетелем, дерево доказательств для командной работы. По умолчанию выключена: [слой disrupt](docs/PLUGINS.ru.md#слой-disrupt--из-чека-о-выполнении-в-экономику-доказательств-экспериментально-по-умолчанию-выключено).

## Приватность

- Локальные модели — локальные данные: ничто не покидает машину, пока *вы сами* не настроите облачного провайдера.
- Удаление чата вычищает его сообщения, артефакты и кэши — приложение ничего не хранит.
- При выходе приложение стирает кэши WebKit; секреты живут только в `.env` / `*.key` — файлах под gitignore.
- Ни телеметрии, ни аккаунта, ни «звонков домой».
