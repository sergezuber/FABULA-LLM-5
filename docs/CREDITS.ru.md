# Благодарности

[English](CREDITS.md) · [中文](CREDITS.zh-CN.md) · [Русский](CREDITS.ru.md)

Движок FABULA происходит от обвязки **MiMoCode** (форк OpenCode). Всё, что построено поверх него —
плагины `fabula-*` и их инструменты, — это **local-first реализация**, выраженная через хуки плагинов
движка и рассчитанная на работу на вашей собственной машине и ваших моделях.

Этот документ сопоставляет каждой возможности **что** это, **где** оно живёт в этом репозитории и — самое
важное — **как убедиться, что оно действительно существует в запущенном приложении.**

---

## Как увидеть эти возможности в приложении

Возможности проявляются четырьмя способами. Некоторые видимы; некоторые поведенческие (вы наблюдаете, что
делает агент, а не кнопку).

| Где | Что вы видите | Пример |
|---|---|---|
| **Панель плагинов** (Настройки → *Плагины*) | Каждый загруженный плагин `fabula-*`, зелёный = здоров | список `40 Plugins` — `fabula-graph`, `fabula-handoff`, `fabula-ops`, … живые |
| **Вызовы инструментов в чате** | Модель вызывает инструмент по имени | `workflow_graph`, `save_handoff`, `schedule_task`, `mixture_of_agents`, `vision_analyze`, `text_to_speech` |
| **Трасса воркфлоу** | Хвост ответа `workflow_graph` | `workflow: 2 isolated step(s)` → `s1(research, cloud) → s2(synthesize, local)` |
| **Поведенческие (хуки / по включению)** | Агент *ведёт себя* иначе — никакого элемента интерфейса | модель жёстко останавливают на повторном чтении файла; веб-результаты приходят обёрнутыми в `<untrusted_tool_result>`; на телефон приходит пуш, когда прогон завершается |

**Возможности «по включению» загружены, но спят, пока вы не выставите переменную окружения** (в `.env`): `FABULA_ROUTER`,
`FABULA_SOULS`, `FABULA_NTFY_TOPIC`. До этого плагин присутствует (зелёный в панели), но поведение выключено.

## MiMoCode / OpenCode — движок, от которого происходит FABULA

**Что:** фундамент, на котором работает FABULA-LLM-5, — цикл агента, система плагинов (хуки `tool.execute.*`,
`chat.*`, `experimental.chat.system.transform`, в которые подключается каждый плагин `fabula-*`),
мультипровайдерный слой моделей (OpenAI-совместимые провайдеры), веб-интерфейс и поддержка MCP.
**Почему:** цикл агента, хуки плагинов, мультипровайдерный слой, веб-интерфейс и поддержка MCP там уже закалены продакшеном; MiMoCode — зрелый форк OpenCode ровно с теми
точками расширения, которые нам нужны, — поэтому движок FABULA строится на нём.
**Где:** всё целиком — `fabula.config.json`, файлы `plugin/fabula-*.ts` и встроенный веб-интерфейс, который хостит приложение для macOS.
**Как увидеть:** приложение хостит веб-интерфейс движка; панели настроек — Коннекторы (MCP), Разрешения, Плагины — идут вместе с ним.

## pi — механизмы надзора, которые мы изучили и адаптировали

**Что:** [pi](https://github.com/earendil-works/pi) (автор Mario Zechner, MIT) — минималистичная обвязка
кодового агента, инженерные заметки о которой сформировали несколько механизмов надзора FABULA. Реализации в
этом репозитории — собственные для FABULA (другой язык, другой движок, покрыты юнит-тестами здесь), но
*конструкции механизмов* ниже восходят к pi и заслуживают упоминания:

| Механизм (происхождение из pi) | Реализация в FABULA |
|---|---|
| Кросс-провайдерный повторный прогон переписки — нормализация и переназначение id вызовов инструментов, синтез результатов для осиротевших вызовов, пропуск ходов с ошибками (pi `transform-messages`) | `plugin/lib/xprovider.ts`, подключено в `plugin/fabula-escalate.ts` |
| Классификация переполнения контекста, включая *молчаливое* усечение (матрица паттернов pi `overflow.ts`) | `proxy/adapter_util.py` → `classify_overflow`, подключено в адаптер `:1235` |
| Телеметрия префикс-кэша — обнаружение момента, когда стабильный префикс промпта сломался и KV-кэш промахнулся (pi cache-stats) | `proxy/adapter_util.py` → `stable_prefix` / `shared_prefix_len` (лог `CACHE-BREAK`) |
| Ограниченный вывод инструментов — ограничить огромные результаты, сбросить полный текст в файл, вернуть курсор продолжения | `plugin/lib/outputcap.ts`, подключено в `bash_tool` |
| Правки, устойчивые к дрейфу, — нормализация типографских кавычек / тире / юникод-пробелов / BOM, чтобы почти-совпавшая правка всё же легла | `plugin/lib/fuzzymatch.ts` (нормализатор `unicode`) |
| Откат переписки при отказе — pi откатывает переписку; FABULA расширяет идею в обе стороны: *атомарный откат файлов* к последнему зелёному чекпоинту теневого git плюс откат дерева переписки, схлопывающий неудавшийся отрезок, чтобы повтор начинался незагрязнённым | `plugin/fabula-rewind.ts` + `plugin/lib/rewind.ts` |
| Экономная выдача инструментов под задачу («набор инструментов» для кодинга, скрывающий нерелевантные) | `plugin/lib/toolbelt.ts` + `plugin/lib/toolmeta.ts` (`FABULA_PROFILE=coding`) |

**Почему:** pi показал измерениями, что надёжность агенту даёт небольшой набор детерминированных механизмов
обвязки, а не модель побольше. Это и тезис FABULA, поэтому мы взяли сильнейшие из этих механизмов и
расширили их (атомарный откат файлов, песочница на уровне ядра, самосрабатывающие гейты).

## Надёжность, безопасность, верифицированное «готово», операции

| Возможность | Где | Как убедиться, что это есть |
|---|---|---|
| **Защита от зацикливания** (жёсткая остановка повторяющихся вызовов без прогресса) | `fabula-reliability` + `lib/loopguard.ts` | Дайте любой модели в сокете задачу, на которой она зацикливается (например, перечитывание одного файла). После нескольких одинаковых вызовов без прогресса её **жёстко останавливают** с указаниями вместо бесконечного цикла. |
| **Починка аргументов вызова** (кривые вызовы и вызовы с лишними ключами всё равно доходят до исполнения) | `fabula-reliability` + `lib/argrepair.ts` | Модель, выдающая слегка неправильную форму аргументов `actor` или инструмента, всё равно отрабатывает, а не падает с ошибкой. |
| **Слой безопасности** (защита от SSRF, маскирование секретов, обёртывание недоверенных результатов, защиты команд и подтверждений) | `fabula-security` + `lib/*` | Попросите агента сделать `web_fetch` страницы — результат вернётся внутри обёртки `<untrusted_tool_result>`; секреты в выводе инструментов и логах маскируются; опасные команды шелла блокируются или требуют подтверждения. |
| **Верифицированное «готово»** (шаг обязан показать свидетельство, что он завершён) | инструмент `verify_done` + пошаговый `verifyStep` в графе | Шаг, вернувший несодержательный вывод — отказ или эхо ошибки, — повторяется один раз, затем помечается деградировавшим, и синтезатору об этом сообщают; провалившийся шаг никогда не течёт дальше как данные. |
| **Инструменты возможностей и операций** | `fabula-ops`, `fabula-multimodal`, `fabula-vision` | Инструменты `schedule_task`, `send_notification`, `vision_analyze`, `text_to_speech`, `transcribe_audio` появляются в чате, когда их используют. |

## Граф воркфлоу + маршрутизатор локальное→облако (local-first)

Граф воркфлоу — **local-first**: локальная модель работает по умолчанию, а облако — включаемый по желанию эскалатор.

| Возможность | Где | Как убедиться, что это есть |
|---|---|---|
| **Граф воркфлоу с изоляцией шагов** — планировщик выдаёт ≤5 подзадач; каждая исполняется как изолированный вызов модели, засеянный *только* выводами своих зависимостей (+ роль + STOP); независимые шаги идут параллельно; результаты синтезируются | `fabula-graph` → инструмент **`workflow_graph`**, логика в `lib/graph.ts` | Вызовите `workflow_graph` на составной задаче. Ответ заканчивается трассой: `workflow: N isolated step(s)` и по строке на шаг (`id(role, local/cloud, needs:[…])`). `fabula-graph` зелёный в панели плагинов. |
| **Маршрутизатор локальное→облако** — правила решают по каждому шагу, достаточно ли он «тяжёлый», чтобы эскалировать на облачную модель | `plugin/lib/router.ts`, включается `FABULA_ROUTER=1` | Выставьте `FABULA_ROUTER=1` и облачный ключ, затем запустите воркфлоу с исследовательским шагом → в трассе этот шаг помечен `, cloud,`, а лёгкие шаги остаются `, local,`. По умолчанию выключено (только локально). |

## Возможности автономного агента

Эти возможности local-first и включаются по желанию.

| Возможность | Где | Как убедиться, что это есть |
|---|---|---|
| **Исходящие пинги событий через ntfy** — пуш на телефон при завершении прогона / ошибке / блокировке защитой от зацикливания | `fabula-reliability`, включается `FABULA_NTFY_TOPIC` | Выставьте `FABULA_NTFY_TOPIC=<topic>` и подпишитесь в приложении ntfy. Завершите прогон / вызовите блокировку защитой от зацикливания → на телефон придёт пуш. |
| **Инъекция курируемой памяти** — ваши рабочие заметки внедряются в системный промпт | `fabula-context` | Модель знает ваши домашние правила (из `.fabula/memory/MEMORY.md`), и их не нужно повторять каждую сессию. |
| **Надёжность планировщика и журнал прогонов** — повторяющиеся и разовые задания через macOS `launchd`, с обнаружением просрочки и захватом результата | `fabula-ops` + `lib/heartbeat.ts`, `lib/schedule.ts` | Вызовите `schedule_task`, затем `list_scheduled` — каждое задание помечено «last ran Xh ago / ⚠️ OVERDUE / never ran». |
| **Ролевые преамбулы** — краткий префикс «кто выполняет этот шаг + STOP» для каждой роли субагента | `plugin/lib/souls.ts`, включается `FABULA_SOULS=1` | С `FABULA_SOULS=1` субагентам actor спереди добавляется короткая преамбула роль/STOP, чтобы любая модель в сокете держалась задачи. |
| **Устойчивые артефакты передачи** — структурированные, просканированные на угрозы передачи между шагами и сессиями | `fabula-handoff` → `save_handoff` / `read_handoff` / `list_handoffs` | Три инструмента появляются в чате при использовании; `read_handoff` возвращает контент обёрнутым и просканированным на угрозы; `fabula-handoff` зелёный в панели плагинов. |
