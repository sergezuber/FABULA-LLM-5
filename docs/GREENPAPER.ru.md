# Greenpaper — Verified Autonomy, v0.2 (черновик)

[English](GREENPAPER.md) · [中文](GREENPAPER.zh-CN.md) · [Русский](GREENPAPER.ru.md)

**«Готово» — это доказательство, а не ощущение.**

## Проблема

ИИ-агенты сами отчитываются о завершении собственной работы. Агент говорит «готово» — проверяет человек.
Чем способнее модели, тем *убедительнее* — но не *правдивее* — их недоказанное «готово», и пользователь
незаметно превращается в отдел контроля качества при собственных инструментах. Способности выросли;
подотчётность — нет.

## Принцип

**Завершение — это событие, которое система может доказать, а не заявление, которое модель может сделать.**

Работа агента *готова* тогда — и только тогда — когда прошла независимая проверка: тесты стали зелёными,
баг перестал воспроизводиться, сборка, обязанная упасть, упала. Уверенность модели — не сигнал
завершения. Если ни одна проверка пройти не может, честное терминальное состояние — *не готово*; сказать
это прямо — не провал, а свойство системы.

## Протокол

Verified Autonomy — минимальный контракт из четырёх частей, не привязанный к конкретной реализации:

### 1. Гейты
Проверку принуждает **система** — её не просят у модели. Оболочка, соответствующая протоколу, содержит
гейты, срабатывающие *сами*:

- **Гейт проверки (verify)** — после правок исходников работа принудительно возвращается на проверку (число повторных заходов ограничено; сессия, остановившаяся после исчерпания лимита, явно помечается как *непроверенная*).
- **Гейт воспроизведения (reproduce)** — ситуация «сборка зелёная, но ни один тест не затрагивает изменение» понижается до *не готово*.
- **Гейт понимания (comprehension)** — прежде чем «готово» засчитается, агента экзаменуют по его собственному diff, а не по самооценке.
- **Гейт обоснованности (grounding)** — для результата **не в коде** (анализ, план, сводка исследования) каждое написанное утверждение перепроверяется по названному источнику: цитата обязана присутствовать в нём дословно (настоящая строка, приписанная не тому разделу, ловится как неверная атрибуция), число — присутствовать, заявление «прочитал все N» сверяется с журналом чтений этой сессии. До карантинной модели, отделяющей честный пересказ от выдумки, доходят только утверждения, не прошедшие бесплатную детерминированную проверку. Так принцип *«готово» — это доказательство* переносится с кода на любой результат: в обычной беседе гейт молчит и устроен по принципу fail-open — обоснованную работу он не отвергает ложно никогда.
- **Защита от зацикливания (loop guard)** — повторяющееся действие без прогресса жёстко останавливается: вместо буксования на месте приходится выдвигать новую гипотезу.
- **Судья остановки (stop judge)** *(v0.1)* — завершить ход решает не модель: прежде чем остановка будет принята, независимый механизм-судья читает стенограмму (реальные вызовы инструментов, а не пересказ модели) и не даёт остановиться, пока запрос не выполнен — именно выполнен, а не запланирован, описан или обещан. Число повторных заходов ограничено, а сам судья по конструкции работает fail-open: сломанный судья никогда не запрёт пользователя.

### 2. Вердикты
Каждая сессия завершается в одном из двух явных состояний: **VERIFIED** (проверка прошла; доказательство
приложено) или **NOT DONE** (проверка не прошла или не смогла запуститься; причина приложена). Третьего
состояния нет. Молчаливая остановка и недоказанное «готово» — нарушения протокола. Это терминальный
контракт протокола; реализованное сейчас принуждение — жёсткий гейт с двумя известными обходными путями:
тяжёлое сжатие контекста и полная передача работы субагенту. Оба описаны в README как открытые границы.

### 3. Чек (Proof of Done) — v0.1
Завершённая сессия выписывает машиночитаемый чек:

```
model:        which weights sat in the socket (id + host, local or cloud)
task:         what was asked
gates:        which gates fired, and what each one forced
artifact:     the diff/patch that shipped
verification: the check that passed (tests, reproduction, build) + its output
replay:       one command that re-verifies the artifact deterministically
provenance:   sha256 of the exact context the model ran with              ← new in v0.1
              (system prompt + wire tool schemas), router profile, and a
              byte-stability verdict — 0 unplanned mid-turn prefix changes
              means the whole run executed on one stable context
```

Блок `provenance` необязателен и живёт только в метаданных: чеки формата v0 остаются действительными, а в
контентно-адресуемую идентичность блок не входит никогда. Два чека с одинаковым хэшем префикса выписаны
в байт-идентичных контекстах: работа воспроизводима не только по артефакту, но и по *контексту*.

v0.2 расширяет блок до полного заявления об идентичности: хэш текста запроса пользователя (фиксируется
в начале хода), дескриптор обслуживающей модели (архитектура/квантизация/издатель; честно помечен как
*не хэш весов*) и, опционально, настоящий дайджест файлов весов на диске. Семантика полей, JSON-схема
и протокол воспроизведения — в открытом черновике спецификации:
[verified-autonomy receipt v0.2](spec/verified-autonomy-receipt-v0.2.md).

### 4. Воспроизведение
Заявления проверяются **воспроизведением артефакта, а не сессии**. Работа LLM недетерминирована; патчи —
детерминированы. Чек, соответствующий протоколу, позволяет любой третьей стороне применить артефакт и
заново запустить проверку (например, патч против тестов задачи в контейнере) — бит в бит, без всякого
доверия к издателю.
Начиная с v0.1 чек ещё и *называет точный контекст*, породивший работу: поверхности проверки печатают
отпечаток префикса рядом с заявлением, так что «на чём это выполнялось» — часть доказательства, а не фольклор.

## Почему это важно

Если результат производит *система*, а доказывает *воспроизведение*, интеллект модели перестаёт быть
потолком результата — и перестаёт быть арендой, которую приходится платить. Маленькая локальная модель
внутри оболочки, соответствующей протоколу, выдаёт работу, которую можно проверить. **Проверенный чек от
модели, которой владеешь, весит больше, чем непроверяемое заявление модели, которую арендуешь. Это про
суверенитет, а не про экономию:** твоя модель, твои данные, твой периметр — а доверие к работе в любом
случае создаёт чек.

## Статус

- **v0.2 — черновик.** Документ фиксирует замысел и форму; формат чека версионируется (v0 → v0.1 происхождение контекста → v0.2 полное заявление об идентичности) и будет версионироваться дальше.
- **Эталонная реализация:** [FABULA](https://github.com/sergezuber/FABULA-LLM-5). Гейты уже существуют в коде:
  verify-гейт сессии в движке (включён по умолчанию, `session/verify-gate.ts` в исходниках движка),
  [reproduce-gate](../plugin/fabula-reproduce-gate.ts), [change-quiz](../plugin/fabula-change-quiz.ts),
  жёсткая остановка циклов в [reliability](../plugin/fabula-reliability.ts). **Выписывание чеков уже
  работает** — плагин [receipt](../plugin/fabula-receipt.ts) (включён по умолчанию): зелёный verify_done,
  который ни один другой гейт не понизил, выписывает машиночитаемый Proof-of-Done — модель, сработавшие
  гейты, diff, проверка и детерминированная команда воспроизведения — в `.fabula/receipts/`
  (`mint_receipt` — выписать вручную). **Терминальный вердикт NOT DONE уже работает** в
  [rewind](../plugin/fabula-rewind.ts): когда лестница самопочинки исчерпана (красная серия, ни разу не
  дошедшая до зелёного состояния, или потраченный бюджет откатов), сессия выдаёт явное `❌ NOT DONE`
  с причиной и списком попыток — никакого молчаливого третьего состояния. **CLI-поверхность уже
  работает**: `fabula receipt` показывает и перечисляет чеки, а `fabula receipt verify` детерминированно
  воспроизводит артефакт — одноразовое рабочее дерево на записанном базовом коммите, применённый патч из
  чека, та же самая проверка — и отвечает VERIFIED или NOT DONE с соответствующим кодом выхода. Публичные
  чеки выпущены: демонстрационный чек, закоммиченный в репозиторий, воспроизводится прямо в нём
  (`cd demo && fabula receipt verify`), а настоящая задача SWE-bench Pro с воспроизведением в Docker одной
  командой лежит в [docs/receipts/](receipts/); остальные свидетельства запусков — в [EVALS.ru.md](EVALS.ru.md).
- Реализации этого протокола другими агентами приветствуются — в этом и смысл.
