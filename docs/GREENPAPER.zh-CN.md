# 绿皮书 —— 可验证自主性，v0.2（草案）

[English](GREENPAPER.md) · [中文](GREENPAPER.zh-CN.md) · [Русский](GREENPAPER.ru.md)

**完成是一份证明，不是一种感觉。**

## 问题

AI 智能体自己汇报自己完成了。智能体说「完成」，人去核对。模型越强，它那句没经过验证的「完成」就越*像真的*——而不是越*是真的*——于是用户不知不觉替自己的工具当起了质检部门。能力已经规模化，问责还没有。

## 原则

**完成必须是系统能够证明的事件，而不是模型自己给出的声明。**

一次智能体运行什么时候算*完成*？当且仅当有一项独立检查通过：测试集变绿，原本能复现的问题不再复现，一个本该失败的构建确实失败了。模型有多自信，不构成完成信号。如果没有任何检查能通过，诚实的终止状态就是*未完成*——而肯把这一点说出来，本身就是一项功能。

## 协议

可验证自主性是一份最小化的契约，不绑定任何具体实现，共四个部分：

### 1. 门禁

验证由**系统**强制执行，而不是向模型提要求。符合规范的框架自带一批门禁，它们*自己*触发：

- **verify 门禁** —— 改完源码，框架把这次运行推回去再走一遍验证（重入次数有上限；若超过上限运行仍然停下，就明确记为*未经验证*）。
- **reproduce 门禁** —— 「构建是绿的，可没有一条测试跑到这次改动」，降级为*未完成*。
- **理解门禁** —— 「完成」要成立，智能体先得对着自己的 diff 接受一次考核，而不是拿自评交差。
- **依据门禁** —— 交付物若**不是代码**（一份分析、一份计划、一份研究摘要），写下的每一条论断都要回到它引用的来源重新推一遍：引文必须逐字出现在它指名的那份来源里（原文确实存在、却挂到了错误的章节，同样算错误归属，照样抓出来），数字必须真的在那儿，「N 项全都读过了」这类说法要拿本次运行的读取日志核一遍。只有没通过这层免费确定性检查的论断，才会送进一个隔离的模型，由它把忠实转述和凭空编造分开。它把*完成是一份证明*从代码延伸到任何交付物上——聊天轮次里一声不吭，而且失效放行，绝不会错杀有依据的工作。
- **循环守卫** —— 同一个动作反复做、又反复没有进展，守卫硬性中止它，逼出一个新假设，而不是原地空转。
- **停止裁判** *(v0.1)* —— 这一轮什么时候结束，不归模型决定：任何一次停止要生效，先得有一位独立裁判读完整条记录（真实的工具调用，不是模型自己写的摘要）；没把请求做完，它就不能收尾——要的是做完了，而不是计划过、描述过或者答应过。重入次数有上限，裁判在设计上又是失效放行——坏掉的裁判永远困不住用户。

### 2. 判定

每一次运行都终止于两个明确状态之一：**已验证**（检查通过，证明随附）或**未完成**（检查没通过，或者根本跑不起来，原因随附）。没有第三种状态。静默停止，以及拿不出证明的「完成」，都算违反协议。这是协议层面的终止契约；已经交付的那套强制实现是一道硬门禁，目前留着两条已知的绕行路径——重度上下文压缩，以及把活整个交给子智能体——README 把这两条都写明为公开的边界。

### 3. 凭证（Proof of Done）—— v0.1

一次完成的运行会签发一份机器可读的凭证：

```
model:        which weights sat in the socket (id + host, local or cloud)
task:         what was asked
gates:        which gates fired, and what each one forced
artifact:     the diff/patch that shipped
verification: the check that passed (tests, reproduction, build) + its output
replay:       one command that re-verifies the artifact deterministically
provenance:   sha256 of the exact context the model ran with              ← new in v0.1
              (system prompt + wire tool schemas), router profile, and a
              byte-stability verdict — 0 unplanned mid-turn prefix changes
              means the whole run executed on one stable context
```

`provenance` 块是可选的，只待在元数据里——v0 凭证依然有效，它也永远不会进入任何内容寻址的身份标识。两份凭证如果前缀哈希相同，那它们就是在逐字节一致的上下文里产生的：这项工作不只在产物层面可复现，在*上下文*层面同样可复现。

v0.2 把这个块扩成完整的身份声明，一共三项：用户请求文本的哈希，在轮次开始时就冻结；正在服务的模型的描述符——架构、量化、发布方，并且老实标注它*并非权重哈希*；以及磁盘上那些权重文件的真实摘要，这一项可选。字段语义、JSON schema 和重放协议都写在开放规范草案里：[可验证自主性凭证 v0.2](spec/verified-autonomy-receipt-v0.2.md)。

### 4. 重放

论断怎么查？**重放产物，而不是重放运行**。LLM 的运行不确定，补丁是确定的。有了一份符合规范的凭证，任何第三方都能把产物应用上去、把验证重跑一遍——比如在容器里拿这个补丁跑任务自带的测试集——逐位一致，不必信任发布者。从 v0.1 起，凭证还会*点名产生这项工作的确切上下文*：验证界面把前缀指纹打印在论断旁边，于是「到底跑的是什么」成为证明的一部分，而不是口耳相传的说法。

## 这为什么重要

结果由*系统*产出、由*重放*证明，模型有多聪明就不再是结果的天花板，也不再是你必须付的租金。一个小的本地模型，放进符合规范的框架里，交出来的活你能自己查。**你自己拥有的模型出具一份已验证的凭证，胜过你租来的模型给出一句无从核对的声明——这讲的是主权，不是成本账：**模型是你的，数据是你的，边界是你的；而让这项工作站得住的，无论如何都是那份凭证。

## 状态

- **v0.2 —— 草案。** 这份文档定的是意图和形态；凭证格式带版本（v0 → v0.1 溯源 → v0.2 完整身份声明），今后也会继续带下去。
- **参考实现：** [FABULA](https://github.com/sergezuber/FABULA-LLM-5)。这些门禁今天已经在代码里了：引擎的会话 verify 门禁（默认开启，见引擎源码 `session/verify-gate.ts`）、[reproduce-gate](../plugin/fabula-reproduce-gate.ts)、[change-quiz](../plugin/fabula-change-quiz.ts)，以及 [reliability](../plugin/fabula-reliability.ts) 里的循环硬性中止。**凭证签发现已交付**，就是 [receipt](../plugin/fabula-receipt.ts) 插件（默认开启）：一次 verify_done 亮绿、又没有别的门禁把它降级，插件就往 `.fabula/receipts/` 里签发一份机器可读的 Proof-of-Done——模型、触发过哪些门禁、diff、验证结果，外加一条确定性的重放命令（想手动签发就用 `mint_receipt`）。**终止的未完成判定现已交付**，落在 [rewind](../plugin/fabula-rewind.ts) 里：自我修复的阶梯走到头时——连着红、一次绿都没到过，或者回退预算花光了——运行会明确给出 `❌ NOT DONE`，附上原因和试过哪些办法，不留静默的第三种状态。**CLI 界面现已交付**：`fabula receipt` 查看和列出凭证，`fabula receipt verify` 确定性地重放产物——在记录下来的基线提交上开一个一次性工作树，把交付的补丁打上去，跑同一套验证——最后报告 VERIFIED 或 NOT DONE，退出码与之对应。公开凭证也已交付：仓库里有一份已提交的演示凭证，可以就地重放（`cd demo && fabula receipt verify`）；[docs/receipts/](receipts/) 里放着一个真实的 SWE-bench Pro 任务，一条 Docker 命令就能重放；更多运行证据见 [EVALS.zh-CN.md](EVALS.zh-CN.md)。
