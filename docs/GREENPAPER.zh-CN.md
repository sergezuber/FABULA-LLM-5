# 绿皮书 —— 可验证自主性，v0.2（草案）

[English](GREENPAPER.md) · [中文](GREENPAPER.zh-CN.md) · [Русский](GREENPAPER.ru.md)

**完成是一份证明，而不是一种感觉。**

## 问题

AI 智能体自己汇报自己的完成。智能体说「完成」；人来检查。随着模型能力增强，它们未经验证的「完成」
变得更有*说服力*——而不是更*真实*——于是用户悄无声息地成了自己工具的质量保证部门。能力已经规模化了；问责没有。

## 原则

**完成必须是系统能够证明的事件，而不是模型可以做出的声明。**

一次智能体运行*完成*，当且仅当一项独立检查通过：测试集通过（绿），复现不再复现，一个必须失败的构建
确实失败了。模型的信心不是完成信号。如果没有任何检查能够通过，诚实的终止状态就是*未完成*——而如实说出这一点本身就是一项功能。

## 协议

可验证自主性是一份最小化、与实现无关的契约，共分四部分：

### 1. 门禁
验证由**系统**强制执行，而不是向模型请求。符合规范的外壳会提供*自触发*的门禁：

- **verify 门禁** —— 源码修改之后，运行会被压回一次验证流程（重入有界；超过上限仍然停止的运行会被明确记为*未经验证*）。
- **reproduce 门禁** —— 「构建通过（绿）但没有任何测试覆盖这次改动」会被降级为*未完成*。
- **理解门禁** —— 在「完成」成立之前，智能体要对照它自己的 diff（而不是它的自我评估）接受评分。
- **依据门禁** —— 对于**非代码**交付物（一份分析、一份计划、一份研究摘要），每一条书面论断都要对照它所引用的来源重新推导：引文必须逐字出现在它所指名的来源中（一句真实的原文被挂到错误的章节，会被判定为错误归属），数字必须确实存在，「已读完全部 N 项」这类论断要对照本次运行的读取日志核对。只有未通过这层免费的确定性检查的论断，才会送到一个隔离模型那里，由它区分忠实转述与编造。它把*完成是一份证明*从代码带到任何交付物上——在聊天轮次中保持沉默，且失效放行（绝不会错误地否决有依据的工作）。
- **循环守卫** —— 反复无进展的动作会被硬性中止，逼出新的假设，而不是原地空转。
- **停止裁判** *(v0.1)* —— 结束轮次不是模型的决定：在任何停止被接受之前，一位独立裁判会读取整条记录（真实的工具调用，而不是模型的摘要），并在请求被满足之前拒绝这次停止——要的是做完，而不是计划过、描述过或承诺过。重入是有界的，而且裁判在设计上失效放行——一个坏掉的裁判永远不会把用户困住。

### 2. 判定
每一次运行都终止于两个明确状态之一：**已验证**（检查通过；证明已附上）或**未完成**（检查未通过或无法运行；原因已附上）。
不存在第三种状态。静默停止和未经证明的「完成」都属于违反协议。这是协议的终止契约；
已交付的强制实现是一道硬门禁，带有两条已知的绕行路径——重度上下文压缩和完全交给子智能体——
两者都在 README 中作为公开的边界记录在案。

### 3. 凭证（Proof of Done）—— v0.1
一次完成的运行会签发一份机器可读的凭证：

```
model:        which weights sat in the socket (id + host, local or cloud)
task:         what was asked
gates:        which gates fired, and what each one forced
artifact:     the diff/patch that shipped
verification: the check that passed (tests, reproduction, build) + its output
replay:       one command that re-verifies the artifact deterministically
provenance:   sha256 of the exact context the model ran with              ← new in v0.1
              (system prompt + wire tool schemas), router profile, and a
              byte-stability verdict — 0 unplanned mid-turn prefix changes
              means the whole run executed on one stable context
```

`provenance` 块是可选的，只存在于元数据中——v0 凭证依然有效，而且它永远不会进入任何
内容寻址的身份标识。两份具有相同前缀哈希的凭证，是在逐字节相同的上下文中产生的：这项工作不仅
在产物层面可复现，在*上下文*层面同样可复现。

v0.2 把这个块扩展为完整的身份声明——用户请求文本的哈希（在轮次开始时冻结）、服务模型的描述符
（架构/量化/发布方；诚实地标注为*并非权重哈希*），以及磁盘上权重文件的可选真实摘要。字段
语义、JSON schema 和重放协议见开放规范草案：
[可验证自主性凭证 v0.2](spec/verified-autonomy-receipt-v0.2.md)。

### 4. 重放
论断的检查方式是**重放产物，而不是重放运行**。LLM 的运行是非确定性的；补丁不是。符合规范的凭证让任何第三方
都能应用该产物并重新运行验证（例如在容器中用该补丁跑任务的测试集）——逐位一致，不需要信任发布者。
从 v0.1 起，凭证还会*指明产生这项工作的确切上下文*：验证界面会在论断旁边打印前缀指纹，
于是「到底跑了什么」成为证明的一部分，而不是口口相传的说法。

## 这为什么重要

如果结果由*系统*产生、由*重放*证明，那么模型的智能就不再是结果的天花板——也不再是你必须支付的租金。
一个小型本地模型，放进符合规范的外壳里，就能交付你可以检查的工作。**来自你自己拥有的模型的一份
已验证凭证，胜过来自你租用的模型的一份无法验证的声明——这是主权，不是成本论证：**你的模型、你的数据、
你的边界，而且无论如何，让这项工作值得信任的正是那份凭证。

## 状态

- **v0.2 —— 草案。** 本文档规定意图与形态；凭证格式是带版本的（v0 → v0.1 溯源 → v0.2 完整身份声明），并将继续如此。
- **参考实现：** [FABULA](https://github.com/sergezuber/FABULA-LLM-5)。这些门禁今天就存在于代码中：
  引擎的会话 verify 门禁（默认开启，引擎源码中的 `session/verify-gate.ts`）、
  [reproduce-gate](../plugin/fabula-reproduce-gate.ts)、[change-quiz](../plugin/fabula-change-quiz.ts)、
  [reliability](../plugin/fabula-reliability.ts) 中的循环硬性中止。**凭证签发现已交付**，即
  [receipt](../plugin/fabula-receipt.ts) 插件（默认开启）：一次没有被其他任何门禁降级的通过（绿）
  verify_done，会向 `.fabula/receipts/` 签发一份机器可读的 Proof-of-Done——模型、触发过的门禁、diff、
  验证，以及一条确定性的重放命令（`mint_receipt` 可手动签发）。**终止的未完成判定现已交付**，
  在 [rewind](../plugin/fabula-rewind.ts) 中：当自我修复阶梯用尽时（一连串失败（红）且从未到达过通过（绿）
  的状态，或者回退预算已经花光），运行会给出明确的 `❌ NOT DONE`，并附上原因与尝试记录——没有静默的第三种状态。
  **CLI 界面现已交付**：`fabula receipt` 展示/列出凭证，`fabula receipt verify` 确定性地重放产物——
  在记录的基线提交上开一个一次性工作树，应用交付的补丁，跑同一套验证——报告 VERIFIED 或 NOT DONE，
  并给出对应的退出码。公开凭证已交付：一份已提交的演示凭证可以在仓库内重放（`cd demo && fabula receipt verify`），
  一个带一条命令 Docker 重放的真实 SWE-bench Pro 任务位于 [docs/receipts/](receipts/)；
  更多运行证据见 [EVALS.zh-CN.md](EVALS.zh-CN.md)。
