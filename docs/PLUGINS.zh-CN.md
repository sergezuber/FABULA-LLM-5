## 这套系统做什么

### 它会动手
带干净抽取的网页获取（HTML→Markdown，包含 PDF）、私有的网页与图片搜索、shell、沙箱化代码执行、精确匹配的文件编辑、一个它能驱动的真实 Chromium、图像分析、文本转语音、转写、天气、地点、定时任务、在会话之间持久留存的交接笔记，以及一张把彼此独立的子步骤并行运行的工作流图。

### 它不会散架

- **循环被切断，而不是被容忍。** 逐字节相同的调用会被硬性中止；换了说法的重复搜索在第二次出现时就被拦下，而每轮不同搜索的预算会逼出综合。
- **差一点的编辑照样落地。** 格式不对的工具调用参数会被即时修复，精确匹配编辑会回落到一个 Unicode 漂移匹配器——弯引号、各类破折号、不换行空格、BOM。
- **传输层有守卫。** 随附的 `:1235` 适配器会抹平推理模型的怪癖、盯住前缀缓存，并标出静默的上下文溢出。
- **输出撑不爆窗口。** 每条命令的输出都有上限，超出的部分带着续读游标溢写到文件，于是一份巨大的测试日志仍然只是一份日志。

### 它不会泄漏
每一次对外请求上的 SSRF 守卫、工具输出里的密钥脱敏、提示词注入防御（不可信的网页内容会被包裹并隔离）、shell 上的命令/审批守卫。

### 它会学
精选的笔记与偏好在会话开始时加载；当你完成*并验证*了一次真正的多步改动之后，它会提醒你把那条轨迹提炼成一个可复用的技能。技能与记忆在会话之间不断累积，全部在端侧完成。

### 它听命遗忘
删除一个对话会彻底清除它的全部产物；网页缓存在退出时清空；没有遥测，没有账号。你允许它学什么它就学什么，你删掉什么它就忘掉什么。

## 逐个插件

| 标签 | 它做什么 |
|---|---|
| `verify` | **外壳的心脏。** `reproduce-gate` 把新测试放到*打补丁前的*代码树上跑——一个加不加这次改动**都**通过的测试是假复现，而一次弄坏同级测试的改动是回归缺陷；两者都会让这次构建停在*未完成*。`change_quiz` 在「完成」成立之前，拿智能体自己的 diff 来考它。`attest` 门禁把同一个想法带到**书面**交付物上——一份分析、一份计划、一份调研摘要。三者都会自触发。[详情 ↓](#attest-门禁) *(`fabula-reproduce-gate`, `fabula-change-quiz`, `fabula-attest`)* |
| `go-audit` | **只管 Go 项目，在别处完全沉默。** 一次 Go 改动通过（绿）之后，六个分析器会在这个模块上跑一遍；如果结果不干净，*完成*会被收回，并附上每一项发现的文件与行号。一个漏洞只有在**可达**时才会拦住你——真的被调用，而不只是出现在 `go.mod` 里。[详情 ↓](#go-安全下限) *(`fabula-goaudit`)* |
| `receipt` | 在一次全门禁通过的绿色验证上签发 Proof-of-Done 凭证——模型、门禁、diff、验证、重放命令，以及这次运行完整的上下文身份（[开放规范草案](spec/verified-autonomy-receipt-v0.2.md)）：提示词前缀指纹、用户请求文本的哈希、服务模型的描述符（诚实地标注为*不是权重哈希*），以及——在 `FABULA_WEIGHTS_DIGEST=1` 时——磁盘上权重文件的真实摘要。 *(`fabula-receipt`)* |
| `graph` | **做计划，并行化。** `workflow_graph` 把一个请求拆成最多 5 个隔离的子步骤，并把彼此独立的那些并行跑起来。步骤之间的边是一份契约：什么都没产出的步骤会以*缺失*的形式抵达，绝不会变成读起来像结果的文本；发生截断时会说明删掉了多少；无法使用的输出会重试一次，然后被标记为空，好让合并知道窟窿在哪里。真正需要多智能体的工作，引擎自带的 `workflow` 工具才是完整的编排器。 *(`fabula-graph`)* |
| `unknowns` | **在动手写代码之前，先补上提示词↔代码库之间的落差。** `reference_hunt` 把能跑的代码当作规范来读；`surface_unknowns` 列出你的需求没有说到的部分；`interview_me` 问出那个只有你才能做的决定；`brainstorm_prototypes` 给出发散的选项。 *(`fabula-unknowns`, `fabula-interview`, `fabula-brainstorm`)* |
| `code` / `files` | **执行，而不是猜。** 有守卫的 shell、沙箱化的 Python/JS、整文件读取、以及在不匹配时拒绝落地的精确匹配 `str_replace` 编辑——不会有静默的损坏。 *(`fabula-tools`)* |
| `web` | 干净的网页获取（HTML→Markdown、PDF）、私有的 SearXNG 搜索、实时天气/地点——不需要任何密钥。 *(`fabula-tools`)* |
| `browser` | 13 个工具驱动真实的 Chromium：导航、点击、输入、截图、控制台、原始 CDP。 *(`fabula-browser`)* |
| `memory` / `handoff` | 会话开始时注入精选记忆；结构化、经过威胁扫描的交接笔记能在会话之间留存下来。 *(`fabula-context`, `fabula-handoff`)* |
| `offload` | **材料放在上下文之外；上下文里只留一个指向它的句柄。** 一个大到装不进本轮的结果会被完整保存在对话之外，取而代之的是一小段说明。随后 `handle_query` 会对*全部*材料提问——由若干独立的子调用按窗口大小的切片读取，再把答案合并——所以没有任何东西被截断，也没有原始材料进入上下文。`handle_peek` 可以逐字读取其中任意一段。这个判断比较的是体积与模型的真实窗口；它从不去读你的措辞。 *(`fabula-handle`)* |
| `corpus` | **一整本书不必塞进一个上下文。** 面对一整份语料时，外壳会把这项工作接管为一次 map-reduce：批次按模型的真实窗口来切，每一批在一次隔离调用里归纳，每份摘要边做边写到磁盘上——中断之后是续跑，而不是从头再来——最后由它们综合出一份报告。触发它的是*工作的形状*（同一个文件夹里一个接一个的文件，超出窗口，还有更多没读），从来不是需求的措辞。 *(`fabula-corpus`)* |
| `window` | **上下文窗口是算出来的，从来不是手打的。** 换模型时，外壳会读这个模型自己的参数表和这台机器的内存，算出真正装得下的最宽窗口，按这个窗口加载模型，并修正后续每一个决策所依据的那个数字。没人量过的数字，永远不被信任。 *(`fabula-window`)* |
| `context-budget` | 不让单个轮次胀出它被分配到的窗口。接近上限时，它会让智能体把已经读到的内容归纳掉，不再抱着原始文本；面对没有边界的「把所有东西都读一遍」这类需求，它会引导到有界的批次加滚动摘要上。在高水位线以下它是惰性（不生效）的，所以普通的一轮保持逐字节相同，不付任何代价。 *(`fabula-ctxguard`)* |
| `checkpoint` | 在智能体动手改之前，把每个文件快照进一个私有的 git 存储——即使项目本身不用 git，也能撤销智能体的改动。 *(`fabula-checkpoint`)* |
| `rewind` | **回退由外壳来做，不是由模型来做。** 当每一次编辑都让验证停在失败（红）时，它会把这些文件回滚到上一个通过的状态——原子地，从它自己的影子 git 里——并引导换一条路，而不是把坑挖得更深。失败的尝试会从模型的上下文里剔除，让重试跑在干净的上下文上（被污染的重试会成倍放大错误），引导指令会点名反复出现的根因特征，而那些被回退掉的尝试留下的非幂等副作用（安装、迁移、网络调用）会被标记为尚未撤销。 *(`fabula-rewind`)* |
| `escalate` | **本地模型卡住时的第二意见。** `escalate_to_cloud` 把同一个问题——试过什么、相关的代码、报的错——发给一个更强的云端模型，拿回一个具体的根因和下一步，好让插槽中的模型不再在死路上打转。模型仍然是一枚可更换的芯片；自动回退的引导指令会把它指到这里，而且在评分认定的连续失败（红）之后，外壳也会自己调用它（受 FABULA_ESCALATE_MAX 约束，终止开关 FABULA_ESCALATE_AUTO=0），而不是指望模型在换过一条路又失败之后自己开口。 *(`fabula-escalate`)* |
| `moa` | 由第二个模型交叉审查这份 diff。 *(`fabula-tools`)* |
| `voice` / `vision` | 文本转语音（带零安装的 macOS 回退方案）、本地 Whisper 转写、带 VLM 自动检测的图像分析。 *(`fabula-multimodal`, `fabula-vision`)* |
| `ops` | 真正的 `launchd` 定时任务，带逾期运行台账和原生通知。`list_scheduled` 是去问 **launchd** 加载了什么，而不是相信磁盘上的文件，所以一个 launchd 从没听说过的残留 plist 会显示为 `NOT LOADED`，而不是一个已就绪的任务。 *(`fabula-ops`)* |
| `reliability` | 循环守卫的硬性中止，以及即时的工具调用修复。（`:1235` 适配器是另一个随附组件：[`proxy/lmstudio-adapter.py`](../proxy/lmstudio-adapter.py)。） *(`fabula-reliability`)* |
| `security` | SSRF 过滤、密钥脱敏、对不可信文本做防注入包裹，以及 shell 守卫——围在每一次工具调用外面。同一套规则覆盖**三道门**：工具、shell，以及模型自己写的代码——后者在操作系统内核配置档下运行。 *(`fabula-security`)* |
| `shipnotes` / `learn` | 自动捕获的修改轨迹 + 偏离记录，打包成一份评审者可以直接看的说明；以及一条把已验证的成果提炼成可复用技能的提醒。 *(`fabula-shipnotes`, `fabula-learn`)* |
| `self-extend` | **模型自己扩充自己的工具带。** 当缺少某项能力时，`create_plugin` 让模型自己写一个新工具；外壳会为它搭好骨架，并在写入之前强制执行「一个文件一个插件」的契约——自己写出来的插件永远不会破坏加载。 *(`fabula-selfextend`)* |
| `tool-router` | **给对的工具，而不是给全部工具。** 在每一条真实的用户消息上，它会确定性地把任务归入一个封闭的配置档（coding / web-research / full），只有该配置档的工具 schema 会送到模型面前——工具 schema 是每个请求里占大头的固定预填充开销——同时这一组在同一个任务内保持逐字节稳定，好让 KV 缓存活下来。被遮蔽的工具如果被按名字调用，仍然会通过影子分发执行：路由器判断失误的代价是一次往返，绝不会是一个被卡住的任务。 *(`fabula-toolrouter`)* |
| `manage` + 日常维护 | 带依赖健康状况的插件启用/停用；一份容量报告，说清这台机器到底是什么（内存类型与大小、核心数、加速器、内核约束、容器）以及由此推导出了什么——窗口策略、同时可以有多少个调用抵达模型，每一项都附上这个数字的来源；整文件读取下限；一个在未审查模型上阻止自动自我改进流程（distill 与 dream 记忆整合）的守卫；删除对话的彻底清除。 *(`fabula-manage`, `fabula-readfloor`, `fabula-distill-guard`, `fabula-purge-hook`)* |

开关状态存在仓库之外（`~/.config/fabula/fabula-state.json` —— 引擎的配置目录；用 `FABULA_PLUGIN_STATE` 覆盖，或者用 `FABULA_DISABLE=browser,ops`）；重启服务后改动生效。

## 两个门禁的细节

### `attest` 门禁

`verify` 与 `reproduce` 决定*代码*算不算完成。`attest` 把同一套标准带到书面交付物上——一份分析、一份计划、一份调研摘要——在那里没有测试可跑。

它把文本拆解成带类型的论断，并逐条重新推导：

- 一条**引文**必须逐字出现在它所引用的来源里（一句真实存在、却被挂到错误章节上的话，会被抓成错误归属）；
- 一个**数字**必须在来源里能找到；
- 像「读完了全部 N 个文件」这样的**过程**论断，会拿这次运行自己的读取日志来核对。

只有没通过这项免费的确定性检查的论断，才会送到一个隔离模型面前，由它把忠实转述与编造区分开。它在闲聊轮次里保持沉默，并且失效放行，所以它绝不会否掉有依据的工作。已在植入缺陷的基准测试上（每一处植入的编造都被抓到，零误报）以及一次实机运行中得到验证。

### Go 安全下限

当一次 Go 改动通过（绿）时，这个模块自己的分析器会跑一遍——`govulncheck`、`gosec`、`staticcheck`、NilAway、`go vet`、`golangci-lint`。如果结果不干净，*完成*会被收回，并附上每一项发现的文件与行号。

**可达性是提高精度的那根杠杆。** 一个已知漏洞只有在有问题的符号真的被调用时才会拦住你——而不只是出现在 `go.mod` 里——所以关于某个用不上的依赖的四条安全公告不会挡你的路，而那一条真实的调用路径会。

在这些 linter 之上，`go_audit_criteria` 会检查大约 30 条没有任何 Go linter 能判定的审查准则：在事务里穿过连接池去读、goroutine 泄漏、被静默跳过的分支、没有上限的查询、过早提交的 Kafka offset、没有 `Reset` 就被复用的 `sync.Pool` 对象。凡是 linter 已经能抓到的，一律声明为不在范围内，而且每一项发现都必须引用 diff 里的一个 `file:line`。

**想检查什么就装什么：**

```bash
brew install go golangci-lint
go install golang.org/x/vuln/cmd/govulncheck@latest
go install github.com/securego/gosec/v2/cmd/gosec@latest
go install honnef.co/go/tools/cmd/staticcheck@latest
go install go.uber.org/nilaway/cmd/nilaway@latest
```

每个分析器都是可选的，而且**每一处缺席都会在报告里点名**——一道单薄的下限绝不会被读成一道干净的下限。只有 `govulncheck` 会报告可达性，所以没有它就根本没有 CVE 检查。在一个没有 `go.mod` 的仓库里，这个插件是惰性的（不生效），不花任何代价。

## 颠覆层 —— 把 Proof-of-Done 变成一套证明经济（实验性，默认关闭）

核心外壳在一次运行结束时会签发一张 **Proof-of-Done 凭证**（`fabula-receipt`）：模型、门禁、diff、确切的验证命令、一条命令即可重放。这六个插件建立*在*那张凭证*之上*——把一件私有的产物变成你可以**发布、被独立认证、被担保、被组合，并因此获得回报**的东西。每一个都是 `defaultEnabled:false`；在**设置 ▸ 插件**里逐个启用，或者通过 `fabula-state.json` 启用。每一个都守着外壳的诚实性纪律：什么都不作假，凭证签发之后绝不再被修改。

| 标签 | 它做什么 |
|---|---|
| `registry` | **一个公开的、内容寻址的证明注册表。** `publish_receipt` 把一张凭证存进分片的内容寻址存储（一棵以 `sha256(patch + verify-cmd)` 为键的文件树，用 git 做版本控制）——同一个修复 + 同一项检查在任何机器上都是同一个 id，所以一份证明不改变它所证明的东西就无法伪造——并且可以把它推送到一个共享的远端仓库。`verify_receipt` 会在记录下来的基线提交上，用一次性 git 工作树重新跑一遍这份证明；`search_receipts` 查询本地索引。只有当某个远端仓库真的持有它时，才会报告一个公开 URL。 *(`fabula-registry`)* |
| `witness` | **独立的跨模型认证。** `witness_diff` 让一个*不同家族*的模型对抗性地审查这份 diff（独立性在模型家族层面强制：见证者不能与作者同一谱系）→ CONFIRMED / DISPUTED，作为一份伴随认证记录在凭证旁边（`.fabula/receipts/witnesses.json`）——凭证本身绝不被改动。一次绿色构建说的是*作者自己的测试通过了*；一位见证者说的是*另一个无法橡皮图章式盖章的角色也同意*。 *(`fabula-witness`)* |
| `daemon` | **KAIROS —— 一种在你离开时仍在签发证明的后台工作姿态。** 打开 `FABULA_DAEMON=1` 之后，它会加上一套诚实的工作姿态（感知缓存的节奏控制、真实的 `gh` PR 活动轮询——没有假的 webhook，以及对终端焦点的感知），好让一次长时间的自主运行在你两次查看之间持续产出已验证、带凭证的工作。时钟循环是引擎的（cron/唤醒）；插件提供的是姿态 + 工具。 *(`fabula-daemon`)* |
| `relay` | **一个有预算的升级循环。** 当插槽中的模型真的卡死了，`relay_to_cloud` 会让一个更强的云端模型把修复写成统一格式 diff——而这份 diff **绝不被信任**：由插槽中的模型来应用它，并重新跑*同一批门禁*。这个循环受尝试次数/成本/时间预算的约束，所以这次运行要么走到 VERIFIED，要么向你提出一个精确的问题——它绝不会悄悄放弃，也绝不会悄悄撒谎。（完整的阶梯——直接做 → 回退重试 → 要建议 → 带提示 → 让云端来写 → 需要你输入——是设计图；`relay_to_cloud` 是已经接上线的那一级。） *(`fabula-relay`)* |
| `coordinator` | **一支智能体团队的供应链溯源。** 当工作被拆给多个 worker（每一个都是真实的引擎子智能体，各自留下自己的凭证）时，`subreceipt_add` 把它们的凭证接成一棵证明树，`proof_tree` 渲染出诚实的合成结果：只有**每一个** worker 的凭证都是 VERIFIED，整体才是 VERIFIED——任何一处 NOT DONE 都会让整次运行成为 NOT DONE。这是一份智能体轨迹的 SBOM：不只是「结果是对的」，而是「每一个 worker 的每一步都被证明过」。 *(`fabula-coordinator`)* |
| `buddy` | **一个只从已验证的工作里成长的伙伴。** 一只小小的 ASCII 宠物，外观由你的用户 id 确定性地决定（你没法靠手改换到一只更稀有的）；它**只**从*通过了*的凭证里获得经验值和等级——一张 NOT DONE 的凭证什么都长不出来。门禁会顶起对应的属性，见证者会成倍放大奖励，而三张各自被 ≥3 位独立见证者认证过的已发布凭证会把它升级成传说级——一枚你伪造不来的徽章。一个静默的钩子会在每一次通过（绿）的验证上喂它，所以让它成长的是证明，不是时间。 *(`fabula-buddy`)* |

把这一层连起来读，它是一个赌注：如果一个本地模型的工作可以被**证明、发布、独立见证、并且组合起来**，那么信任就不再取决于是哪个模型产出了它。*任何模型插入 —— 产出可证明的工作。*

## 适用于任何支持工具调用的模型

| 运行时 / 提供商 | 怎么做 |
|---|---|
| **LM Studio**（本地） | 默认路径——经由随附的 `:1235` 适配器，它会为推理模型抹平结构化调用/工具调用的差异 |
| **Ollama 及其他本地服务器** | 与 LM Studio 相同的 OpenAI 兼容 `baseURL` 路径——端到端的验证运行尚未完成 |
| **任何 OpenAI 兼容的云** | 在 `fabula.config.json` 里加上 `baseURL` + 密钥——引擎自带一份庞大的内置提供商预设目录 |
| **企业网关（LiteLLM 等）** | 严格要求单条 system 消息的端点由 `fabula-context` 处理 |

基础系统提示词（[`system-prompt.example.md`](../system-prompt.example.md)）是原创的、与模型无关的——一份你可以在上面继续搭建的公开模板。把它复制成 `system-prompt.md`（配置里 `instructions` 指向的路径），就能跑你自己的版本。
